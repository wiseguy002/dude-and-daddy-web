# Putting dudeanddaddy.com on Cloudflare

This folder is the studio website. Nothing to build or install.

    site/    -> dudeanddaddy.com

The game, Clean Up On Aisle Scream!, is NOT part of this site. It has its own repo
(wiseguy002/clean-up-on-aisle-scream) and deploys itself to https://cleanuponaislescream.com
(see that repo's docs/cloudflare-setup.md). Every game button and link here goes there, and
dudeanddaddy.com/game/ forwards there (the `_redirects` file does it).

Do NOT add a redirect rule or any project for cleanuponaislescream.com from this repo.
The game's own Worker owns that domain.

## One-time setup (already done)
1. dudeanddaddy.com is on Cloudflare (Free plan, Cloudflare nameservers).
2. The site is a Cloudflare **Worker** named `studio` (Workers & Pages, `studio`), connected to this repo with
   Workers Builds: every push to `main` runs `npx wrangler deploy`, and every other branch gets a preview
   (`npx wrangler preview`). There is no build step. `wrangler.jsonc` is the whole configuration.
3. Custom domains on the Worker: dudeanddaddy.com and www.dudeanddaddy.com.
4. SSL/TLS: Full (strict), Always Use HTTPS.

Branch previews need their own copy of any storage binding: see the `previews` block in `wrangler.jsonc`. A new
binding added at the top level must be added there too (pointed at a test resource), or the branch build fails.

## The news list (the site's one bit of server code)
The home page's "Store News" form, `/news/confirm/` and `/news/unsubscribe/` talk to `worker/index.mjs` at `/api/*`.
Everything else is still plain files. A sign-up sends a confirmation email; the address joins the list only when the
link in it is clicked. Subscribers are in the Cloudflare KV namespace `studio-signup` (keys `sub:<email>`). To see them:
Storage & Databases, KV, `studio-signup`. Mail goes through Resend from `beepboopmail.com`.

Three secrets on the `studio` Worker (Settings, Variables and Secrets), never in this repo:

    RESEND_API_KEY   the Resend key named dude-and-daddy-2 (sending only, beepboopmail.com only)
    EMAIL_FROM       Dude & Daddy <dudeanddaddy@beepboopmail.com>
    SIGNUP_SECRET    a long random value that signs the confirm and unsubscribe links
                     (changing it breaks every unsubscribe link already sent: do not rotate it casually)

Without all three the form answers "the mail room is closed" and nothing is sent or saved.
Tests: `node --test tests/*.mjs`.

### Sending news
Each confirmed address is also copied into the Resend segment **Dude & Daddy news** (`NEWS_SEGMENT_ID` in
`wrangler.jsonc`), and removed from Resend when that person leaves. To send: resend.com, **Broadcasts**, Create,
choose that segment, send from an address at `beepboopmail.com`, and keep Resend's unsubscribe link in the footer
(it is in the default template; in custom HTML it is `{{{RESEND_UNSUBSCRIBE_URL}}}`).

The copy only happens when `RESEND_API_KEY` on the `studio` Worker is a **full access** key. With a sending-only key
sign-ups still work and are kept in KV, but they do not reach the segment: add those people to the segment by hand,
or ask Claude to copy them across.

Note: `site/index.html`, `site/privacy/index.html` and the two `/news/` pages were edited by hand for this. If the
pages are regenerated by the site builder, carry the "Store News" section, the privacy text and the
`<script src="/news/signup.js">` tag across.

## Updating
Commit a change to main. Cloudflare publishes it in about a minute. Other branches get a
preview link (public to anyone who has it; previews cannot send email or see the real list). Roll back any time from the Deployments tab.
